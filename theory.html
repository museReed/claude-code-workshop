T1 — 15 min

為什麼要學 AI Agent

你用過 ChatGPT 嗎？大部分人都用過。但你有沒有想過，為什麼你還是得自己動手做事？

ChatGPT 是「你問它答」—— 你得自己複製貼上、自己開檔案、自己整理。

AI Agent 是「你說它做」—— 它直接幫你建檔案、寫內容、跑指令。

ChatGPT

打電話問朋友怎麼組家具，朋友在電話裡講步驟，你自己動手。

Claude Code

朋友直接來你家，你說要什麼，他幫你組。

2026 年為什麼重要：AI 從「對話工具」變成「執行 Agent」。會下指令的能力，會變得跟會用 Excel 一樣基本。

T2 — 25 min

Terminal 是什麼

終端機是「用打字跟電腦對話的工具」。你平常用滑鼠點資料夾、開檔案 —— terminal 做的是同一件事，只是把點擊換成打字。

圖形介面（GUI）

像去餐廳內用 —— 看菜單、用手指點。

Terminal（CLI）

像直接打電話給廚房，用特定詞彙告訴主廚你要什麼。兩者做的事一樣，方式不同。

為什麼工程師愛用 Terminal？

更快、某些工具只有 terminal 版、可以自動化。而且 —— Claude Code 住在 terminal 裡。

$ 符號叫做提示字元（prompt）—— 意思是 terminal 在等你打指令。

6 個必學指令

pwd

我在哪？
Print Working Directory
顯示你現在在電腦的哪個資料夾

ls

這裡有什麼？
List
列出當前資料夾的內容

cd folder-name

進入某個資料夾
Change Directory
移動到指定的資料夾

cd ..

回上一層
.. 代表「上一層」

mkdir name

建立新資料夾
Make Directory
建立一個新的資料夾

touch name

建立新檔案
建立一個空白檔案

實際操作長什麼樣

$ pwd
/Users/student/Desktop
$ ls
homework.pdf  photos  notes.txt
$ cd photos
$ pwd
/Users/student/Desktop/photos
$ ls
vacation.jpg  graduation.jpg

你不需要記住所有指令。只要記住：pwd（我在哪）、ls（有什麼）、cd（去哪裡）。其他的，問 Claude Code 就好。

T3 — 30 min

Git 與 GitHub

你有沒有存過「報告_v1.docx」「報告_v2_final.docx」「報告_v2_final_真的最終版.docx」？Git 就是解決這個問題的工具。

Git = Google Docs 的版本紀錄功能，但更強大。它記住每一次修改的「是什麼」「誰改的」「為什麼改」。

GitHub = 把你的版本紀錄放上雲端，別人也能看到、協作。同時也是你的「程式作品集」。

只要學 3 個指令

git add .

選取要存檔的改動
像購物車「加入」—— 把你改過的檔案放進準備區

git commit -m "說明"

確認存檔，附上說明
像「結帳」—— 正式存下這次的改動，附一句說明

git push

推上 GitHub
像「寄出」—— 把本地的紀錄同步到雲端

完整流程

改動檔案 → git add → git commit → git push → GitHub

今天的 workshop 結束時，你會把你的練習成果用這三個指令推上 GitHub，變成你的作品集。

T4 — 20 min

Model → Product → Agent

AI 的世界分三層。理解這三層，你就知道 Claude Code 在哪裡、為什麼它跟 ChatGPT 不一樣。

第一層

Model 模型

底層的 AI 引擎。像汽車的引擎 —— 你看不到它，但所有能力來自它。

例：Claude Opus、GPT-4、Gemini

第二層

Product 產品

把模型包裝成你能用的東西。像整台車 —— 有方向盤、座椅、儀表板。

例：ChatGPT、Claude.ai、Gemini App

第三層

Agent 代理

產品加上「動手能力」。像自動駕駛 —— 車子自己開、自己導航、自己停車。

例：Claude Code、Cursor Agent、Devin

Product vs Agent 差異

Product（如 ChatGPT） Agent（如 Claude Code）
位置 瀏覽器 你的電腦 terminal
能力 回答問題 讀/寫檔案、跑指令
互動 你複製貼上 它直接改你的檔案
比喻 電話諮詢 到你家幫忙

我們今天要學的是第三層 —— Agent。具體來說，是 Anthropic 的 Claude Code。

T5 — 30 min ⭐ 最重要

怎麼跟 AI Agent 溝通

跟 AI Agent 溝通，不是「打字聊天」。是「指揮一個很厲害但沒有 context 的新同事做事」。你給的指令越精確，它做出來的東西越接近你要的。

官方四階段工作流

這是最重要的一步，Anthropic 官方放在第一條。

你必須在開始之前就知道「成功長什麼樣」。

例：要 Claude 整理文獻 → 驗證標準是「每篇都有作者、年份、期刊名、跟我的研究問題的關聯」。

讓 Claude 先讀現有檔案、了解狀況，不要一上來就改。

用 plan mode（Shift + Tab）讓 Claude 只看不動。

請 Claude 列出它打算怎麼做，你審完才讓它動手。

「先告訴我你的計畫，不要直接做。」

Claude 寫 code / 建檔案 / 跑指令。

完成後用 Stage 1 定好的標準驗證。

指令對比：Before / After

範例 1 — 學術場景

「幫我整理文獻」

「讀 references/ 資料夾裡的 5 篇 PDF。幫我建一個 literature-matrix.md，每篇列出：作者、年份、研究方法、主要發現、跟我的研究問題『AI 對管理決策的影響』的關聯。完成後確認 5 篇都有，沒有遺漏。」

範例 2 — 求職場景

「幫我改履歷」

「讀 resume.md 和 job-description.txt。根據 JD 裡的關鍵要求，調整履歷的 bullet points，讓每條都對應到 JD 的某個要求。不要編造經歷。完成後列出『JD 要求 vs 履歷對應』的對照表讓我確認。」

範例 3 — 生活場景

「幫我找房子」

「讀 apartments.md 裡的 8 間房源資料。幫我做一個比較表，欄位：地址、月租、通勤時間到 KCL Strand、是否含帳單、房東評價。按月租排序。」

進階技巧：讓 Claude 反過來問你

大型任務不知道怎麼寫指令？讓 Claude 反過來問你。

我想做 [簡短描述]。先詳細問我需求：
問技術實作、邊界條件、取捨。
問到清楚為止，然後寫一份完整 spec。

記住這四步：驗證 → 探索 → 規劃 → 執行。
驗證放第一步，是因為你不知道怎麼判斷對錯的話，給再多 context 也沒用。

T6 — 20 min

CLAUDE.md 與 Skills

讓 Claude Code 每次開工都記得你的偏好和規則。

CLAUDE.md = 給 AI 的 Onboarding 手冊

你的經驗

你新進一家公司，第一天會拿到員工手冊：公司規定、做事流程、注意事項。

CLAUDE.md

Claude Code 的員工手冊 —— 它每次開始工作前都會讀。你的偏好、規則、禁忌，全寫在這裡。

範例 CLAUDE.md

# 我的專案

## 關於我
我是 KCL Technology Management 碩士生，研究 AI 對管理決策的影響。

## 規則
- 用繁體中文回答
- 學術內容必須附出處，不可以編造引用
- 檔案命名用英文小寫加連字號（如 literature-review.md）

## 不要做的事
- 不要幫我寫 critical analysis 的核心論點
- 不要編造不存在的文獻

Skills = 可重複使用的指令模板

你每天早上到公司都會做同一套動作（開信箱、看行事曆、泡咖啡）。Skill 就是把這套動作寫成一個「一鍵執行」的模板。

今天會安裝的 4 個 Skills

HUD

狀態列，顯示 Claude Code 現在在幹嘛。像車子的儀表板。

auto-rename

自動幫對話取名字，之後好找。

structured-question

Claude 要問你問題時，用選項而不是散文（更好回答）。

handoff

工作到一半要交接時，自動產生交接文件。
