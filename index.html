時長

課程概覽

為非工程師設計,給未來管理工程師的人

科技管理的工作從來不是寫 code,而是理解、評估、指揮它這個工作坊訓練第三項,「指揮」,用 Claude Code 當教具

01
理解
Understanding
明白技術原理,不必精通,懂到能問出對的問題
02
評估
Evaluation
判斷技術價值與風險,決定什麼值得做、何時做、由誰做
03
指揮
Direction
指揮 AI / 工具完成目標,這個工作坊聚焦在這

工作坊結束後,你應該能

  1. 區分 LLM / AI Product / AI Agent 三層,這不是學術分類,是工作上做決策時的根本問題
  2. 用 CCC 框架(Context, Constraints, Check)下指令,讓 AI 真正執行你要的事
  3. 在 terminal 啟動 Claude Code,完成一個跟你真實生活有關的小任務
  4. 知道 AI 在學術場景的紅線(Academic Integrity),這比知道 AI 能做什麼更重要
  5. 認識 CLAUDE.md、Agentic Workflow 等進階概念,不必精通,知道存在就夠

第 0 章 · 5–8 min · 開場

我們為什麼要在這裡?

三個問題,三個誠實的答案

No. 01

AI 工具一堆,為什麼是這個、為什麼是現在?

2026 是 AI 從「對話工具」變成「會做事的同事」的拐點學會指揮它,是這個世代科技管理者的基本功,不是選修

No. 02

第 4 章 · 25 min · 溝通框架

如何跟 AI 溝通,CCC 框架

大部分「AI 不行」其實是「我給的指令爛」三個字母解決大半科技管理者最重要的 AI 技能,跟最重要的非 AI 技能一樣,清楚地下達指令

Context
背景
任務、輸入、目標讀者、現有檔案,AI 需要知道你站在哪
Constraints
限制
格式、長度、能/不能做什麼、依賴條件,AI 需要知道邊界在哪
Check
驗證
AI 給的我有沒有當真?有沒有抽查?採納還是丟掉?,這是你最不能外包的事
範例 01
會議筆記
Bad,請你猜
幫我整理一下會議筆記
Good,請你做
讀 raw_notes.txt(三週會議生肉),拆成 week1/2/3.md,每週包含:出席、決議、Action Items(Owner / Task / Due / Status)跨週用 tracker.md 推斷 ✅/⏳/⚠️ 狀態原句不清楚的標 [paraphrased]
CCC 對應: Context = 三週生肉 / Constraints = 結構化欄位 + 推斷狀態 / Check = 標記不清楚的句子
範例 02
倫敦找房
Bad,請你猜
找便宜的房子
Good,請你做
我下個月搬倫敦讀 KCL Strand,預算 £1,400 全包,通勤 < 45 分鐘,不要 6 個月押金讀 listings.md 8 筆房源 + criteria.md,輸出 comparison.csv + shortlist top 3 + red_flags.md(掃 Tenant Fees Act 違法條款)
CCC 對應: Context = 個人背景 + 兩個輸入檔 / Constraints = 預算 / 通勤 / 押金 + UK 法律 / Check = 紅旗清單
範例 03
履歷對標
Bad,請你猜
修一下我的履歷
Good,請你做
讀 cv_draft.md(我的)+ job_description.md(目標 PM Grad)先解構 JD 成 Required/Preferred/Implicit 三層;再對標 CV 標 ✅/⚠️/❌;只改寫 ⚠️ 命中項目,不可編造數字,改不了的標 [needs data]
CCC 對應: Context = 兩個檔 / Constraints = 不編造數字、只改命中項 / Check = [needs data] 標記
Bad 是 「請你猜」,Good 是 「請你做」三個範例都對應第 5 章你等下會選的場景,記住模板,自己跑時套上去

CLAUDE.md,AI 的 onboarding 手冊

你不會每次都跟新人重講公司規矩,你寫一份文件丟給他CLAUDE.md 就是那份文件

類比 · 新員工 onboarding 包

公司簡介→## 專案是什麼
慣例 / 風格→## 設計規範
技術棧 / 工具→## 技術棧
Code of Conduct→## 注意事項
「別碰 X」→## Don't

想像你是第 5 章 Scenario D 的學生,你自己的論文資料夾應該長什麼樣:

CLAUDE.md
放在論文資料夾根目錄
# Dissertation Project

## 這份論文是什麼
MSc Technology Management dissertation, 12,000 字標題: Generative AI Adoption in UK SMEs繳交期限: September 2026
## 我的研究問題
How do UK SMEs move from ad-hoc AI tool use
to durable organisational capability, and what
determines success?

## 我的 supervisor 偏好
- 重批判推論 > 文獻摘要
- 討厭 "It is clear that..." "Many scholars argue..."
- 要 Harvard referencing,in-text 不要 footnote
- 沒 empirical 支撐的 claim 一律退稿

## 我要 AI 怎麼幫我
- 把 outline 變成資料夾結構
- 當 critical reviewer,指出矛盾與弱點
- 整理我的讀書筆記,依主題分類
- 找出我自己沒注意到的章節連結

## ⚠️ Don't
- 不要寫任何一章的 argument 或 analysis
- 不要編造我沒讀過的論文 citation
- 不要替我下「這個領域認為...」的結論
- 不要生成任何結論段
沒有 CLAUDE.md,AI 每次都用「通用工程師」的思維幫你做事有了它,AI 一開始就知道你的脈絡、品味、紅線你下指令的字數可以省一半,品質還更好
