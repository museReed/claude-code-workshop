Part 1 · 10 min

AI 術語暖身

確保所有人在同一個起跑線，不因術語卡住後面的實作。

術語 白話解釋 類比 為什麼你要知道
LLM 讀過海量文字後學會「接話」的 AI 模型 讀過整個圖書館的實習生 ChatGPT、Claude 背後都是 LLM
AI Agent 能自主規劃步驟、使用工具、完成任務的 AI 系統 LLM 是大腦，Agent 是有手有腳的員工 Claude Code 就是一個 Agent
Prompt 你給 AI 的指令或問題 你對實習生說的那句話 最重要的職場技能之一
API 軟體之間溝通的標準介面 餐廳的菜單和點餐窗口 評估技術方案可行性
CLI 用打字下指令操作電腦 跟電腦用文字訊息溝通 Claude Code 就是 CLI 工具
Terminal 執行 CLI 的那個視窗 電腦的聊天室 安裝和操作都在這裡
IDE 工程師寫程式用的全功能編輯器 Word 寫文章，IDE 寫程式 VS Code 是最常見的 IDE
Repository 專案所有檔案 + 完整修改歷史 Google Drive + 每次修改都有備份 團隊協作的基礎
Git 追蹤檔案修改歷史的版本控制系統 Google Docs 版本紀錄但更強大 Claude Code 內建 Git 操作
2 層揭露法：先講 4 個標有 CORE 的術語（LLM → AI Agent → CLI / Terminal → Prompt），其餘用到再講。

AI 的三個層級

理解 LLM、Product、Agent 的差異——你未來做採購決策時，要分清買的是什麼。

LLM模型
Claude Opus 4.6GPT-4oGemini 2.5 Pro
Product產品
ChatGPTClaude.aiGemini App
Agent代理
Claude CodeCursorWindsurf

ChatGPT vs Claude Code

💬 ChatGPT / Claude.ai

互動方式貼東西給它，回文字給你
工作流程複製 → 貼 → 拿回覆 → 複製回去
處理範圍一次一段對話，上下文有限
能做的事回答問題、生成文字
你的角色操作員（手動搬運每一步）

⚡ Claude Code / Cursor / Windsurf

互動方式直接讀寫電腦檔案、跑程式
工作流程告訴它做什麼，自己找改測
處理範圍整個專案資料夾，數百檔案
能做的事建檔案、執行程式、分析數據
你的角色管理者（下指令、審核結果）

同一任務的對比：分析 100 份問卷

用 ChatGPT
1. 打開 CSV，複製前 50 行（有字數限制）
2. 貼到 ChatGPT：「幫我分析」
3. 發現沒看到完整資料，再貼後 50 行...
4. 給你一段 Python code
5. 自己找地方跑，跑出錯
6. 複製 error 貼回去問...
7. 來回 10 次，圖表終於出來
8. 想改顏色？再來一輪...
用 Claude Code
你：「讀 survey.csv，跑 descriptive stats，
     做 cross-tab，輸出圖表到 charts/」

Claude Code：
  ✓ 讀取 survey.csv（全部 100 筆）
  ✓ 執行 pandas 統計分析
  ✓ 生成圖表
  ✓ 存到 charts/age_vs_adoption.png

你：「改深色背景，字體放大」
  ✓ 修改設定，重新生成
核心觀念：從「對話」到「委派」
你的想法
→
AI Agent
→
檔案系統
→
程式執行
→
完成品

這不只是效率差異，是工作模式的轉變——從「我操作工具」變成「我管理 AI 去操作工具」。

Part 4 · 25 min

如何跟 AI 有效溝通

Technology Manager 最重要的 AI 技能——下指令。

C

Context

背景：你在做什麼、為什麼

C

Constraint

限制：技術棧、時間、範圍

C

Criteria

標準：什麼叫「做好了」

❌ Bad Prompt
"Make me a website"
✓ Good Prompt
"Build a responsive landing page for a SaaS product using HTML/Tailwind. Include hero section, 3 feature cards, and a CTA button. Mobile-first."

練習 2

場景：「你的團隊需要一個內部工具追蹤 OKR」。用 CCC 框架寫出 prompt，讓 Claude Code 建出 MVP prototype。

Part 5 · 50 min

分組實作：學術場景

每組 3-4 人，從以下情境中選一個。點擊展開詳細資訊。

A

Literature Review 加速器

批量處理 PDF 論文，自動提取重點生成比較表

⭐⭐⭐ 20-25 min
展開 ↓

Steps

  1. 讀取單篇 PDF，提取 research question / methodology / findings / limitations
  2. 批量處理，輸出結構化 CSV 比較表
  3. 根據比較表識別 research gap
"Read this PDF and extract: (1) research question, (2) methodology, (3) sample size, (4) key findings, (5) limitations. Output as CSV row."

Output

literature_matrix.csv + gap analysis

Skills

  • 檔案批量處理
  • 結構化 prompt 設計
  • 迭代精修欄位
Academic Integrity：可以整理比較。不可以直接生成你沒讀過的 critical analysis。
B

Group Project 會議追蹤

雜亂會議紀錄 → 結構化 minutes + action item tracker

⭐ 15-20 min
展開 ↓

Steps

  1. 貼上 raw meeting notes，整理成 structured minutes
  2. 生成 tracker.md，checkbox 追蹤 TODO
  3. 下次開會前 diff 上週 tracker，標出 overdue
  4. 累積 3 週後生成 progress summary
"Organize into: (1) Key Decisions, (2) Action Items with owner and deadline, (3) Open Questions. Then update tracker.md."

Output

meetings/weekN.md + tracker.md

Skills

  • 非結構化 → 結構化轉換
  • 檔案持續維護
  • 跨 session 累積使用
Academic Integrity：完全 OK — productivity tool，無學術誠信疑慮。
C

問卷數據快速分析

100 份 CSV 問卷 → 統計分析 + 圖表 + findings 初稿

⭐⭐⭐ 25-30 min
展開 ↓

Steps

  1. 讀取 CSV，產出 descriptive statistics
  2. 生成 Python 腳本跑 cross-tabulation
  3. 自動產出圖表（matplotlib/plotly）
  4. 根據結果撰寫 findings 段落初稿
"Read survey.csv. Run descriptive stats. Cross-tabulate Q3 (age) against Q7 (adoption). Generate stacked bar chart for academic paper."

Output

analysis.py + charts/ + findings_draft.md

Skills

  • 數據分析自動化
  • 圖表客製化迭代
  • 程式碼生成與執行
Academic Integrity：生成分析腳本 OK。AI 寫的 findings 只能當初稿，你必須驗證每個數字。
D

Reference 管理與格式轉換

散落引用 → 統一 Harvard style + 一致性檢查

⭐⭐ 15-20 min
展開 ↓

Steps

  1. 把各種格式引用資料解析成統一 JSON
  2. 轉換為 Harvard referencing style
  3. 檢查 in-text citation vs reference list 一致性
  4. 產出缺失引用 + 幽靈引用報告
"Parse references into structured fields. Format as Harvard style. Cross-check against paper for missing or orphan citations."

Output

references_harvard.md + citation_audit.md

Skills

  • 格式解析與轉換
  • Cross-referencing
  • 品質檢查自動化
Academic Integrity：完全 OK — 格式化工具，等同 Zotero / Mendeley。
E

Dissertation 結構化寫作助手

大論文拆小檔案，AI 當 writing coach 逐章 review

⭐⭐ 20-25 min
展開 ↓

Steps

  1. 根據 outline 建立資料夾 + 檔案結構
  2. 每個檔案填入 writing prompt（問題、source、字數）
  3. 寫完一節後讓 AI review 邏輯連貫性
  4. 合併所有 section，檢查 transition 和 flow
"Create folder structure with one .md per section. Include: key question, suggested sources, word count target, connection to previous section."

Output

folder structure + review_feedback.md

Skills

  • 大型文件拆分管理
  • AI 作為 reviewer 而非 writer
  • 迭代改進
Academic Integrity：組織思路 + review 邏輯 = OK。生成 argument + 寫結論 = 不 OK。

情境選擇建議

只有 30 min 實作B（最直覺、人人有感）
45 min，展現多面向B + D（流程管理 + 格式自動化）
60 min，分組各做A / B / C / D 各一組，最後 demo 互學
想引發最深討論C 或 E（academic integrity 灰色地帶最多）
技術門檻（低→高）B → D → E → A → C

Part 6 · 15 min

AI Governance & Judgment

Technology Manager 必須思考的問題。

能力邊界

  • Claude Code 能做什麼、不能做什麼？
  • 現場測試邊界——故意給它做不到的事
  • 理解 hallucination 的風險

安全意識

  • API keys 不要硬寫在 code 裡
  • 生成的 code 要 review，不要盲信
  • Permission model 存在的原因

組織導入

  • 誰該用？怎麼用？ROI 怎麼算？
  • Code review 流程怎麼調整？
  • IP / 資料安全政策

成本結構

  • ChatGPT 月費吃到飽 vs. Agent 按 API 用量計費
  • 影響你的預算規劃
  • 不同場景選不同工具
