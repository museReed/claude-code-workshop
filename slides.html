第六章 · 進階觀念

設定分兩層

只要記住：一個跟著「你」走，一個跟著「專案」走。

User Level

跟著你這個人

~/.claude/
  • 所有專案都會套用
  • 適合個人偏好、語氣、工作習慣
  • 只在你的電腦上生效
Project Level

跟著這個專案

專案資料夾/.claude/
  • 只在這個專案內生效
  • 適合團隊規範、專案規則
  • 可以跟 repo 一起共享
選擇原則：個人習慣放 User Level；專案或團隊規則放 Project Level。兩邊衝突時，Project Level 優先。

進階 · 讓 Agent 自己動手

讓 AI 不用每次都問你

預設每個動作都要你按一次「同意」。上手後，可以「授權」AI 在安全範圍內自動執行，你只看結果——快很多，但要先分清楚哪些能放手。

全手動

每一步都問你。最安全，但一直被打斷。

半自動 ★

安全的事自動做，危險的事才停下來問。今天的甜蜜點。

全自動

什麼都不問。最快也最危險，留給拋棄式環境。

🎚 模式（總開關）

一鍵決定 AI 整體有多放手：只讀 → 自動改檔 → 全自動。

白名單的常見雷

加了白名單，為什麼還是問我？

現象：你明明把 git status 加了白名單，AI 一跑 git status && npm test 又跳出來問。

原因（一句話）：AI 會把 &&、|、; 這種「一行串多個指令」拆開逐一檢查——只要其中任何一個沒在白名單，整串就停下來問你。npm test 沒加，所以就算 git status 是信任的，還是被卡住。

解法 ① ★ 最推薦
拆成一條一條跑

「一條指令做一件事」，不要串 &&。每條都能對上白名單，最穩。

解法 ②
把每個子指令都加

串裡用到的每一個都放進白名單，例如再加 Bash(npm test:*)。

解法 ③
用更寬的規則

整組放行，如 Bash(git *)、Bash(npm *)。方便但信任範圍變大。

✓ 優先選 ① ——就是我們一直在講的「一條指令一件事」，白名單命中率最高，也最容易看懂 AI 每一步在做什麼。

實作 · 開始動手

開始生成網站

▶ Step 01 · 準備素材 — 萃取 CV 核心資訊

讀 exercises/career/resume-tailoring/cv_draft.md，
萃取這份 CV 的核心資訊（姓名、學歷、經歷、技能、專案），
整理成一份 Landing Page 的內容大綱。

▶ Step 02 · 生成頁面 — 用 /frontend-design 產出

用 /frontend-design 幫我建立一個個人品牌 Landing Page。

內容來源：剛才整理的 CV 大綱
風格方向：簡潔專業、深色主題、適合科技管理背景
頁面結構：Hero（姓名+一句話定位）→ About → Experience → Projects → Contact
要求：單一 HTML 檔、RWD、不依賴外部框架

產出到 index.html

▶ Step 03 · 預覽 — localhost 確認效果

幫我啟動一個 local server 預覽 index.html。
看完後我會告訴你要調整什麼。

📸 下載 Snipaste 免費截圖工具 — 截下畫面直接貼給 AI Agent，讓它看著圖修 UI
▶ Step 04 · 發布 — 推到 GitHub + 開啟 Pages

幫我建立一個新的 GitHub repo 叫 wei-chen-portfolio，
把 index.html 推上去，然後用 GitHub Pages 發布。
完成後給我公開網址。

⚠️ Pages 網站永遠是公開的——repo 可以設 private（免費帳號的 private repo 開不了 Pages），但網址任何人都能看。電話、地址等不想公開的資訊不要放上去。
